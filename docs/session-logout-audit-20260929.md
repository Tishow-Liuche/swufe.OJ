## 结论及证据边界

已确定旧实现存在会把暂时故障转成退登的软件缺陷；已核对当前公开网站和认证后端包含修复。**无法证明用户之前某一次退登必定由哪一个请求触发**：服务未开启完整访问日志，没有前端退登原因事件，且未取得该次浏览器请求记录。不能将“缺陷可以复现”表述成“历史事件的唯一原因已查明”，也不能承诺之后零故障。

## 确定的软件机制

1. 访问 JWT 有效期 900 秒。过期本身正常，必须由 HttpOnly Cookie 支持续期；不是每 15 分钟要求重新登录。
2. 旧版 `47cc6fc` 的 `api/client.ts` 在续期 catch 中无条件清除访问令牌并跳转登录。`stores/auth.ts` 的资料读取、会话恢复也将任何异常当成退出依据。短暂网络失败、限流和服务端错误因此会被误判为身份失效。
3. 旧版后端先删除旧会话，再单独创建替代会话；中途数据库失败可让会话丢失。多个标签页无跨页锁，还可能争抢同一个单次使用的续期 Cookie。
4. 仅把轮换放进事务仍不能解决“服务器提交成功，浏览器没收到新 Cookie”的问题。已上线版本提供精确后继会话恢复：旧 Cookie 配合同一次随机重试标识，在五分钟内恢复仍存在的后继会话。无效、撤销、错误标识均不得恢复。

当前行为：429、5xx 和网络异常不清登录；同页请求合并续期；支持 Web Locks 的浏览器跨页串行续期；轮换在事务内完成；旧异步响应不能覆盖较新的本地登录状态。主动退出、清除 Cookie、会话真正过期、账户删除等安全原因仍可能要求登录，不能为了保证“不退登”而放行无效身份。
