# 本地判题完整性修复与验收（2026-09-20）

## 范围

修复普通题与 SPJ 的评测结果解释、沙箱故障识别、提交版本绑定及录题版本更新。未修改主页、用户密码、历史提交、比赛成绩或训练服务器资源配置；不自动重判历史提交。

## 修复内容

- 新录 SPJ 默认 `BOOLEAN_STDOUT`：正常退出且明确输出布尔结果才算有效判定。空输出、无效结果、判题程序崩溃或超时为 `SYSTEM_ERROR`，不计部分分。
- `EXIT_CODE`：正常退出码 0 为 AC，1/2 为 WA；其他退出码、信号及沙箱故障为系统错误。打印 False 但退出 0 **不是** WA。录题页切换协议仅替换未编辑的默认 Python 模板，绝不改写作者代码。
- 现有 SPJ 保留 `LEGACY`，编辑页明确提示：无输出、正常退出仍表示 AC。不能凭源代码猜测协议。旧题需要作者验题后主动选择明确协议。
- 保留沙箱原始状态、退出码、信号、错误及 stderr；缺失成功输出流、缺失编译产物、HTTP 错误和损坏响应不再被当成正常成功。
- 沙箱请求包含墙钟限制和 HTTP 完整响应截止时间，文件清理也有超时。
- 实机发现 go-judge 的 OLE 同时返回 `CollectSizeExceeded` 文件信息；仅精确匹配 stdout/stderr 的该类超限信息时保持 OLE。SPJ 自身 OLE 仍是系统错误。语法错误导致编译产物缺失仍保留 CE。
- 评测读取 `Submission.problemVersionId`，不读取最新版本代替原版本。已记录但无效的版本拒绝评测；只有历史空版本 ID 保留兼容回退。
- 修改题面、评测代码、测试数据或时空限制创建新版本。事务与逐题 PostgreSQL advisory lock 串行化发布；旧测试数据不删除。
- SPJ 转普通题必须先置草稿，新版本清空输入型数据，重新上传成对输入输出后才能发布。
- 学生提交详情不暴露隐藏测试数据及 SPJ 内部错误信息；教务诊断保留。比赛详情按比赛管理权限处理。

## 可重复的诊断脚本

在已配置数据库/Redis、已构建且有实际 worker 的受控环境中执行：

```sh
JUDGE_INTEGRITY_AUDIT=1 node scripts/check-judge-version-live.cjs
JUDGE_INTEGRITY_AUDIT=1 node scripts/check-judge-integrity-live.cjs
```

两脚本会创建、修改和删除隔离测试账号与题目，非只读检查。禁止在正式比赛中运行。队列脚本逐项串行执行，不作为压测；报告为 `/tmp/judge-audit-report.json`。若仍有活动任务，脚本保留测试对象以避免删掉正在评测的数据，需等待任务结束后人工检查清理。录题脚本使用真实数据库事务，管理权限接口被替代，仅验证服务的数据一致性，不验证鉴权。

## 边界

- 评测机只能忠实执行作者提供的检查规则，不能证明任意 SPJ 算法正确。永远输出 True、漏验测试用例、提前返回成功等逻辑缺陷仍需验题发现。
- 非当前的历史版本没有时空限制记录时，无法恢复未知历史配置，保留队列限制回退；迁移只回填可确认的当前版本。
- 通过本次回归不等于任何负载下永不故障，也不构成比赛容量保证。
