# 提交与判题反馈修复

## 已确认原因

- 旧判题循环在 TLE 后仍继续执行余下测试点。
- 提交准入拒绝任何已有未完成提交的账号；同时存在快速判题后状态被覆盖回 QUEUING 的竞态。
- 旧前端每1.5秒轮询、45秒便停止本地结果查询；新提交未隔离旧请求。
- 远端判题机逐点写云端数据库；实测5次预热后的SELECT1耗时670/1747/444/447/444ms。显示的timeUsed是测试点最大CPU运行时间，不是端到端等待时间。

## 修复

- TLE持久化后停止后续测试点，未执行点不计通过；WA继续测以保留部分分逻辑。
- 第1个测试点先保存，其后最多10个测试点或1秒间隔批量保存；每批单条参数化PostgreSQL语句完成原子替换，异常时保存已完成结果。重试/停滞重启清理旧测试点，正常首次执行不增加该数据库往返。
- 默认每账号最多5个未完成提交，保留5秒间隔及500队列上限（含优先级队列）；数据库锁串行化同一账号的准入。入队失败释放占位。
- 页面只在发送请求时禁用按钮；初期500ms查询，之后退避；请求不重叠、取消旧请求、延迟响应不能覆盖新提交，列表持续更新其它待完成提交。程序运行时间明确标注，排队不再45秒即放弃。

## 验证及边界

- 前端48项测试通过；判题处理器24项、提交服务14项测试通过。
- 真实PostgreSQL验证25个点保存与重复处理，无重复记录。
- 浏览器验证连续提交、旧响应隔离、比赛提示隐藏和主页未改动。
- 第一轮真实端到端：TLE仅执行1/25点（CPU5999ms，提交至judgedAt28429ms）；第二份在第一份未完成时成功提交，25/25 AC（最大CPU4ms，提交至judgedAt20861ms）。
- 最终版本再次实测：TLE 1/25点，CPU6000ms/整体14445ms；AC 25/25点，最大CPU4ms/整体11763ms。两次结果受链路波动与连接预热影响，不能把差值当作固定性能提升比例。
- 本次不提高判题机并发、CPU或内存配额。跨服务器网络仍有明显延迟，不能承诺毫秒级端到端结果；外站排队由外站控制。
